# Phases 33–36 (owner round 5) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the owner's round-5 feedback on 1.0.252: Copy / Cut / Paste with a "+" mark, no hint line, ‹ › only, zoom on Adjust's page only, ID cards placed by hand and side by side, PRINT back at once, and Delete on Recent jobs.

**Architecture:**
- **Copy, Cut and Paste:** a copied photo is a new job item pointing at the same file (`copyOf`). Paste puts the copy, or a cut photo restored, on the page shown, placed by hand.
- **ID cards** get their own hand places (`idCard.spots`, mm centres) and an arrangement (`idCard.arrange`) in the plan. Adjust drags them through the existing hold-and-drag hook, which is generalised from photos to keys.
- **The print screen:** the native print flow records whether Android asked for the final file. A screen closed before that is "notSent" at once.

**Tech Stack:** Preact + TypeScript (web), Kotlin (Android plugin), Vitest, Playwright, JUnit, AndroidX instrumentation + UiAutomator.

**Spec:** `docs/superpowers/specs/2026-10-25-round-5-copy-paste-cards-drag-zoom-print-back-design.md`

## Global Constraints
- **Unchanged rules:** offline, ₹0, no new dependency.
- **Customer files** are parsed only in the isolated engine, and no image bytes cross the bridge.
- **One geometry (the plan) for both preview and print;** exact sizes; 300 dpi at the box.
- **Plain English** (the jargon lint); anything pressed is at least 56 px; every gesture has a button that does the same; "Remove animations" is respected.
- **Back and Home never lose work** without the shopkeeper saying so.
- **Startup JS** ≤ 61,440 B gzip (`node scripts/size.mjs` after `npx vite build`).
- **Testing:** every behaviour change is test-first (watch it fail). Full e2e (`npx vite build --mode e2e && npx playwright test`) and `npm run verify` before each commit.
- **Tasks 5 and 8 also change `android/`:** their commits run Android lint + JVM tests in the hook.
- **Device scripts** run only on 5580, 5560 and 5566; never on 5554.

## Review Focus
1. **Paste after the cut photo's job was left and opened again:** the remembered photo is gone; Paste is greyed out, and nothing crashes or pastes into another job. Test in Task 3.
2. **Copy, then Remove the original, then Paste:** the copy is still made from the remembered settings, because the file stays in the job folder. Test in Task 3.
3. **A card placed by hand, then Big size or Turn right:** it stays centred where it was, inside the page's margins. Test in Task 6.
4. **A print screen that asked for the final file and then failed:** it is not "notSent"; the result screen still says what happened. Test in Task 8 (JVM: `finalAsked` true + no job → CHECKING then NOTHING_PRINTED).
5. **Delete all while a job is open underneath:** the open job is kept, as Settings' Delete all does. Test in Task 9.

### Task 2: A copy is a photo of its own (33a, job model)

**Files:** Modify `src/core/job/job.ts`. Test: `src/core/job/job.test.ts`.

**Interfaces:**
- **Produces:**
  - `JobItem.copyOf?: number`.
  - Action `{ type: 'copyItem'; from: number; page: number; x: number; y: number }`. x and y are the mm centre on that page.
  - `nextItemIndex(job: Job): number`, exported. It is the `used`-aware next index that addItems already computes, extracted.
- **Behaviour of `copyItem`:**
  - The new item is `{ ...fromItem, index: n, copyOf: from }`.
  - It copies `turns[from]`, `tilts[from]`, `crops[from]`, `quads[from]` and `sizes[from]` (when present) to n.
  - `order` gets n inserted right after `from`.
  - `spots[n] = { page, x, y, z: top + 1 }`. It needs `job.spots`: the caller sends setSpots first.
  - `duplicates` are unchanged: `duplicateGroups` ignores items with `copyOf`.
  - `from` not in items: no change.
- **normalizeJob** keeps `copyOf` when it is a number of an existing item; otherwise it drops the field.

  - `a copy is never "the same photo sent twice"`.
  - `copyItem of a removed photo changes nothing`.
  - `nextItemIndex never reuses a number a removed photo still holds`.
  - `normalizeJob keeps copyOf only for a real item`.

### Task 6: ID cards placed by hand and side by side (35, model + plan)

**Files:** Modify `src/core/job/job.ts`, `src/core/plan/plan.ts` (`idCardPlan`). Tests: `src/core/job/job.test.ts`, `src/core/plan/idcard.test.ts`.

**Interfaces:**
- **Produces:**
  - `IdCardChoice.spots?: Record<number, { x: number; y: number; z: number }>` (mm centres, page 0).
  - `IdCardChoice.arrange?: 'row'` (none = one under another).
  - Actions:
    - `{ type: 'placeIdCard'; at: number; x: number; y: number }`: on top, `z` = max + 1.
    - `{ type: 'setIdCardArrange'; arrange: 'stack' | 'row' }`: clears `spots`.
    - `{ type: 'clearIdCardSpots' }`.
  - `setIdCards` (new cards) clears `spots`. `normalizeJob` validates both: finite numbers, indexes of cards, `arrange === 'row'` only.
- **`idCardPlan`** for sizes real, big and custom:
  - **Row:** `fit = min((wMm − 2e − gaps)/sumW, (hMm − 2e)/tallest)`; the cards are side by side, centred, with a 10 mm gap, each centred vertically in the row.
  - **Then spots:** each card with a spot gets its box centred on its spot (same size), clamped inside the edges.
  - **Drawn order:** by `z` (unplaced first), so the last placed is on top.
  - **Guides** follow the boxes.
  - **Sets and page:** spots and arrange are ignored.
